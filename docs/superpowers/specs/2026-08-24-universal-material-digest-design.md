# Jelly 多格式稳定材料提炼设计

日期：2026-08-24
状态：等待用户复核
目标体验：用户 10 分
前置设计：`2026-08-22-inspiration-material-digest-design.md`
目标分支：`codex/jelly-inspiration-material-digest`

## 1. 结论

Jelly 采用“格式优先的统一材料管线 + 薄平台适配器”，不再按平台各自实现获取、转写、摘要和保存整条链路。

主链只有一条：

```text
原始输入
  → 识别来源和可用获取方式
  → 提取正文、时间轴转写、OCR 或文档文本
  → 生成可复用的标准化材料快照
  → 检查内容是否足够、是否只有部分内容
  → 直接摘要或分块摘要
  → 生成带原文位置依据的 MaterialDigest
  → 用户审阅并确认写入笔记
```

平台适配器只负责取得公开内容。B 站、小宇宙、小红书以及后续平台取得内容后，都进入同一套质量门禁、长文本处理、摘要、失败恢复和笔记写入流程。

产品承诺不是“所有互联网链接永远抓得到”，而是：

1. 能取得足够内容时，稳定生成有来源依据的摘要；
2. 只取得标题或零散元数据时，不生成假摘要；
3. 平台受限或改版时，保留原始来源，并给用户粘贴文字或提供文件的继续路径；
4. 任何失败都不破坏原始灵感、旧摘要或既有笔记。

## 2. 复杂度必要性审查

### 2.1 当前已经具备的能力

- `Inspiration` 已能表达文字、URL 和文件三种原始输入，以及文章、社交帖子、音视频、图片和文档等来源类型。
- `MaterialDigest` 已有独立运行状态、来源 checksum、旧结果保留、取消、失败、结构化摘要、provenance 和确认写入笔记的闭环。
- B 站和小宇宙已经验证了“公开字幕优先、必要时下载音频、本机 Whisper、OpenAI 兼容模型摘要”的路径。
- 本机已有 AVFoundation 和 WhisperKit；macOS 14+ 可直接使用 PDFKit 与 Vision，不需要增加 Python、浏览器服务或常驻进程。

### 2.2 当前必须

- 用标准化材料快照替代“所有内容都是 `TimestampedTranscript`”的假设。
- 让来源解析按具体能力/平台分流，而不是把所有 `.video` 都交给 B 站、所有 `.audio` 都交给小宇宙。
- 支持正文、时间轴转写、图片 OCR、PDF 页文本四类内容块，并保留其原文位置。
- 把已完成的内容提取持久化；模型失败、重启或重试摘要时不得重新下载和转写。
- 对长材料分块处理，避免超过模型上下文后直接失败或截断 JSON。
- 每条主要结论和引用必须绑定原材料块，不允许模型用标题或元数据补造事实。
- 为公开小红书视频和图文笔记增加专用适配器。
- 平台获取失败时，提供粘贴正文或选择本地文件继续提炼的恢复路径。
- 保留主动提炼、写入再次确认、原始链接永不被派生内容覆盖的交互合同。

### 2.3 可以延后

- 登录态、私密内容、付费内容、DRM、直播和需要验证码的来源。
- 评论区、点赞、收藏、转发等互动数据。
- Word、Excel、PowerPoint 等 Office 文件。
- 视频逐帧视觉语义理解；第一阶段处理音轨、页面正文、字幕和代表性画面中的文字。
- 一次性接入所有 `yt-dlp` 平台。
- 后台定时自动提炼和跨设备后台继续运行。

这些能力只在真实用户材料反复因其失败、且更小的粘贴/文件回退不能满足时重新评估。

### 2.4 应当删除

- 仅凭 `.video`、`.audio` 类型决定平台适配器的路由。
- 为网页、图片和 PDF 伪造时间戳，以便塞进转写稿模型。
- 只拿标题、封面或几句元数据就生成看似完整的摘要。
- 把 Python、`yt-dlp`、无头浏览器或新后台服务变成 Jelly 的必需运行环境。
- 为每个平台复制独立的摘要、持久化和 UI 状态机。

## 3. 产品对象和责任边界

### 3.1 Inspiration：用户原始来源

`Inspiration` 继续保存用户实际提供的文字、URL 或文件引用，以及轻量来源元数据。捕获后立即落盘，网络或模型失败不影响它。

原始内容不可被摘要、OCR 或转写覆盖。来源变更后，旧材料快照和旧摘要必须因 checksum 不匹配而失效，但仍可供用户查看历史结果，不能写回当前来源。

### 3.2 MaterialSnapshot：派生的来源快照

新增 `MaterialSnapshot`，它是可复用的来源/过程证据，不是新的用户一级 Artifact。它回答“本次摘要实际看到了什么”，不回答“内容意味着什么”。

它保存：

- 绑定的 `inspirationID` 和 `sourceChecksum`；
- 标准化内容块；
- 获取方式和适配器版本；
- 内容指纹；
- 是否足够摘要、是否只覆盖部分内容；
- 已处理和未处理的内容说明；
- 创建时间。

材料提取完成后先原子保存快照，再开始模型摘要。摘要失败或 App 重启后，只要来源 checksum 和快照指纹仍匹配，重试直接复用快照。

### 3.3 MaterialDigest：派生摘要

`MaterialDigest` 仍然是依附于 Inspiration 的派生结果，不新建知识库或独立文档系统。

摘要保存：

- 核心论点；
- 带证据引用的主要观点；
- 带证据引用的章节/主题；
- 保留原语言的直接引用；
- 被判断为广告、片头片尾、重复噪声等内容；
- 摘要模型、合同版本、材料指纹和生成时间。

### 3.4 Note：用户确认后的工作成果

提炼成功只产生可审阅 Digest。只有用户明确点击“写入笔记”后，才把原始来源和结构化摘要写入既有 Note。

写入必须继续满足：同一条灵感只有一篇转换笔记；更新摘要只替换上次由 Digest 写入的块，不触碰用户后来编辑的块。

## 4. 10 分用户旅程

### 4.1 捕获

用户可以粘贴文字、链接，或选择支持的本地文件：

- 原始输入立即保存，不等待网络、OCR、Whisper 或摘要模型。
- URL 只在后台做轻量来源识别和标题解析，不自动消耗摘要额度。
- 界面显示“已保存原始内容”；来源识别失败时仍然可以打开原始链接。
- 同一捕获入口不要求用户先判断这是文章、视频、图片还是播客。

### 4.2 主动提炼

详情中始终使用同一个主操作“提炼这份材料”。点击后在下一次可见 UI 更新中进入处理态，不允许按钮静默无反应。

用户看到的是少量、真实的人话状态：

- 正在读取材料；
- 正在识别音频；
- 正在识别图片文字；
- 正在整理长材料；
- 正在生成摘要。

内部可以有更多阶段，但不得把技术步骤和虚假百分比暴露给用户。只有能测得真实总量时才显示百分比；否则显示持续活动和已经完成的阶段。

用户可以离开详情页、切换灵感或取消处理。取消后应在 1 秒内给出可见反馈，迟到的网络或模型结果不得写回。

### 4.3 结果审阅

成功结果先显示：

- 一句话核心论点；
- 3～7 条主要观点；
- 主题/章节；
- 关键引用；
- 本次实际读取的材料范围。

每条主要观点可以展开查看依据：视频/音频显示时间点，PDF 显示页码，图片显示图片编号，网页显示正文段落。依据点击后优先定位到 Digest 内保存的原文；来源仍可访问时再提供打开原来源。

完整材料默认折叠，不把长转写稿或 OCR 文本直接淹没摘要。

### 4.4 部分内容和失败恢复

如果只取得部分但已足够摘要的内容，结果必须明显标注“基于部分内容”，并列出未处理部分，例如“3 张图片中 1 张未能识别”。用户可以接受结果或补充材料后重新提炼。

如果内容不足，不生成摘要，提供与失败原因对应的下一步：

- 平台限制：粘贴正文、选择截图、音频或视频文件；
- 页面只有标题：粘贴正文；
- 图片文字过少：补充说明或更多图片；
- 音频无有效语音：改用文字说明或其他文件；
- 模型未配置：打开模型设置；
- 模型失败：复用已保存材料快照重试，不重复获取来源。

旧的成功摘要在重试期间继续可读。失败、取消和部分成功都不得删除原始输入。

### 4.5 写入笔记

用户确认写入后，笔记第一块永远是原始来源，后续才是核心论点、主要观点、主题和必要引用。完整材料快照留在 Digest 中，不默认写入笔记。

任何不确定写入都进入“继续确认写入”，不得静默重复创建笔记。

## 5. 第一阶段正式支持范围

“支持”表示能够取得有效正文、通过内容质量门禁、生成带依据摘要，并通过最终 App 的代表性真实场景。只识别域名或标题不算支持。

| 输入 | 内容获取 | 第一阶段合同 |
| --- | --- | --- |
| 直接文字 | 原始文字 | 完整支持 |
| TXT / Markdown / HTML 文件 | 本地解码与正文清理 | 完整支持 |
| 公共文章网页 | HTML 正文提取 | 内容不足时明确失败并允许粘贴正文 |
| B 站公开视频 | 公开字幕优先，音轨 + Whisper 回退 | 保留现有能力并迁入统一管线 |
| 小宇宙公开单集 | 公开音频 + Whisper | 保留现有能力并迁入统一管线 |
| 小红书公开视频笔记 | 页面正文、话题、公开视频音轨；必要时代表性画面 OCR | 新增直接支持 |
| 小红书公开图文笔记 | 页面正文、话题、全部公开图片 OCR | 新增直接支持 |
| 本地音频 | Whisper | 完整支持 |
| 本地视频 | 音轨 + Whisper，代表性画面 OCR | 明确标注不包含完整视觉语义理解 |
| JPEG / PNG / HEIC | Vision OCR | 完整支持可识别文字；纯视觉内容标注能力边界 |
| 数字 PDF | PDFKit 页文本 | 完整支持 |
| 扫描 PDF | PDFKit 渲染 + Vision OCR | 完整支持可识别文字 |

不在第一阶段支持列表中的域名可以尝试公共文章正文提取，但界面不得展示为已正式支持的平台。

## 6. 标准化材料合同

建议领域形态：

```swift
public struct MaterialSnapshot: Codable, Equatable, Sendable {
    public let sourceChecksum: String
    public let contentFingerprint: String
    public var blocks: [MaterialBlock]
    public var coverage: MaterialCoverage
    public var provenance: MaterialAcquisitionProvenance
    public var createdAt: Date
}

public struct MaterialBlock: Identifiable, Codable, Equatable, Sendable {
    public let id: MaterialBlockID
    public var role: MaterialBlockRole
    public var text: String
    public var locator: MaterialLocator
    public var confidence: MaterialConfidence?
}

public enum MaterialBlockRole: String, Codable, Sendable {
    case body
    case transcript
    case ocr
    case metadata
}

public enum MaterialLocator: Codable, Equatable, Sendable {
    case paragraph(index: Int)
    case timestamp(startSeconds: Double, endSeconds: Double)
    case page(number: Int)
    case image(index: Int)
}

public enum MaterialCoverage: Codable, Equatable, Sendable {
    case sufficient
    case partial(processed: Int, expected: Int?, issues: [MaterialCoverageIssue])
    case insufficient(code: MaterialInsufficiencyCode)
}
```

最终实现可以调整命名，但必须保留以下语义：

- 内容块有稳定 ID 和可显示的位置；
- `metadata` 只能帮助拼写、命名和上下文，不计入“内容足够”的阈值，也不能成为事实依据；
- 覆盖问题和内容不足原因使用有界、可校验的枚举，用户文案由 App 映射，不把页面或模型返回的任意字符串写进领域状态；
- `partial` 不等于失败，但摘要和写入笔记都必须保留其覆盖说明；
- 内容指纹由规范化后的有效块计算，模型、时间和适配器诊断不得进入指纹；
- 内容块按原始顺序保存，最大数量和字符数受领域上限约束。

旧 `TimestampedTranscript` 解码为一组 `.transcript + .timestamp` 内容块。新代码不得为非时间轴内容生成虚假时间点。

## 7. 获取与提取架构

### 7.1 SourceResolver

`SourceResolver` 根据输入种类、URL host/path、文件 UTType 和轻量探测结果生成具体 `SourceDescriptor`。路由键必须包含能力或平台身份，不能只返回 `.video`、`.audio` 这类展示分类。

示例：

```text
bilibiliVideo
xiaoyuzhouEpisode
xiaohongshuNote
publicWebArticle
localText
localImage
localPDF
localAudio
localVideo
```

### 7.2 MaterialAcquirer

每个 Acquirer 只负责把一个明确来源变成原始资产或内容候选，不负责调用摘要模型和持久化结果。

公共网络获取继续使用同一套安全 HTTP 客户端：

- 只允许公开 HTTPS；
- DNS 和重定向都拒绝本机、私网、保留地址和降级到 HTTP；
- HTML、图片、字幕、音视频分别有大小和重定向上限；
- 请求头按平台最小化设置，不读取用户浏览器 Cookie；
- 日志不记录分享 token、Cookie、完整查询串或临时文件路径。

本地文件通过安全作用域 bookmark 访问，任务结束后停止访问；原文件不复制进 Workspace。需要持久化的只有标准化文本快照，不保存原媒体副本。

### 7.3 FormatExtractor

格式提取器只做确定性转换：

- HTML：使用固定版本、经过依赖与许可证审查的离线 HTML parser，移除脚本、样式、导航和重复模板，保留正文段落顺序；不使用联网 WebView 作为正文获取主链；
- 音频：Whisper 生成时间轴文本；
- 视频：抽取音轨并转写；按受控采样选取代表性画面做 OCR，重复文字去重；
- 图片：Vision OCR，保留图片序号；
- PDF：优先 PDFKit 页文本；无有效文本的页面单独渲染 OCR；
- TXT/Markdown/HTML 文件：安全解码、字符集和内容上限检查。

提取器不使用模型补写缺失正文。OCR 或转写失败只影响对应资产；其余内容足够时形成 `partial` 快照，否则形成 `insufficient`。

### 7.4 平台适配器

#### 小红书

- 只识别公开 `explore/<id>` 和 `discovery/item/<id>` 笔记，以及确认安全的官方分享重定向。
- 从公开页面状态读取笔记类型、标题/正文、话题、图片列表和视频资源。
- 视频笔记把页面文字、音轨转写和代表性画面 OCR 合并；图文笔记处理全部公开图片。
- 分享 token 只用于当前请求，测试 fixture、日志、快照和提交中不得保存真实 token。
- 页面结构缺失、需要登录或公开资源不可用时返回平台限制/来源不可用，不回退到仅标题摘要。

#### B 站和小宇宙

现有解析器保留，但移入平台适配器注册表。字幕、音频和 Whisper 的选择成为该适配器的获取策略，输出统一 MaterialBlock。

任何一个平台改版只允许影响自己的适配器，不得改变标准化材料、摘要模型或其他平台的运行。

## 8. 内容质量与摘要

### 8.1 内容质量门禁

质量门禁只统计 `body`、`transcript` 和 `ocr`：

- 过滤空白、Whisper 特殊标记、重复转写噪声、重复 OCR 和页面模板；
- 检查有效语义量和多样性；
- 检查预期资产是否处理完成；
- 区分 `sufficient`、`partial` 和 `insufficient`；
- 标题、作者、站点名和标签等 metadata 不得把不足内容升级为足够。

阈值必须通过代表性中英文 fixture 和真实材料校准，不能只用“包含几个汉字”之类单一启发式。

### 8.2 小材料直接摘要

在保守输入预算内的材料使用一次结构化请求。模型输入明确把来源内容标记为不可信数据，材料中的指令不得改变系统合同、输出结构或安全限制。

派生字段默认简体中文；直接引用、专有名词和完整原文保持原语言。

### 8.3 长材料分块摘要

超过保守输入预算后：

1. 按内容块边界切分，不截断句子、时间段或页面；
2. 每块生成结构化 `DigestShard`，所有观点携带原 MaterialBlock ID；
3. 最终综合只读取 shard 和必要的短原文窗口；
4. 综合结果的每条主要观点必须能追溯到至少一个原 MaterialBlock；
5. 无法解析或无依据的 shard 失败，不用空结果继续合成；
6. 模型重试只复用已保存 MaterialSnapshot，不重新抓取、OCR 或转写。

具体 chunk 大小根据当前端点/模型的安全预算计算，不把 MiniMax 某个版本的上下文长度写死进领域模型。

第一阶段不持久化每个 shard，避免引入第二套可恢复任务系统；若真实长材料反复因 App 中断造成明显成本，再以 MaterialSnapshot 为边界增加 shard cache。

### 8.4 摘要证据合同

摘要合同升级，主要观点、主题点和直接引用均引用 MaterialBlock ID。Validator 必须检查：

- 引用的块存在；
- 直接引用文本确实出现在附近原文中；
- 时间、页码、图片和段落位置来自块 locator，不由模型自由填写；
- metadata 块不能成为唯一事实依据；
- 部分内容的覆盖说明不会在写入笔记时丢失。

## 9. 运行状态、并发与恢复

建议运行阶段：

```swift
public enum MaterialDigestStage: String, Codable, Sendable {
    case resolvingSource
    case fetchingSource
    case extractingText
    case transcribing
    case recognizingImages
    case preparingSummary
    case summarizing
    case awaitingModelDownloadConsent
    case downloadingModel
}
```

UI 将这些内部阶段映射成人话状态，不一一展示技术名词。

现有 `inspirationID + runID + sourceChecksum` 并发门禁保留，并增加 `contentFingerprint`：

- 迟到结果不能覆盖取消、重试或变更来源后的运行；
- 摘要只接受当前保存的材料指纹；
- 重试摘要可复用当前快照；
- 用户要求重新读取来源时才丢弃旧快照并重新获取；
- 清理临时媒体失败不能把已成功的摘要改成失败。

App 重启后的行为：

- 尚未保存快照的外部工作标为“上次处理被中断”，允许重试；
- 已保存快照但未完成摘要的运行标为“材料已就绪，可继续生成摘要”；
- 旧成功结果继续可读；
- 等待模型下载确认的状态保持可继续，不自动下载。

## 10. 持久化、迁移与回滚

`WorkspaceDocument.currentSchemaVersion` 从 4 升到 5，因为新结果不再强制包含 `TimestampedTranscript`，且新增可复用 MaterialSnapshot。

迁移规则：

- V4 `MaterialDigestResult.transcript` 逐段映射为 V5 transcript blocks；
- 旧 summary 的时间点通过相邻 transcript block 还原证据引用；无法安全还原的普通观点保留文本，但标记为 legacy evidence，不伪造新依据；
- Validator 按摘要合同版本分支：迁移得到的 legacy 结果允许只读展示和重新提炼，新合同生成的结果必须通过完整证据门禁；legacy 结果不得在重新生成时绕过新合同；
- 原 Inspiration、Note、旧成功摘要、note-write 回执和来源 checksum 不丢失；
- V5 编码后再次解码必须得到相同快照、摘要和引用；
- 迁移或校验失败时不得覆盖当前可读 Workspace；
- 升级前保留可恢复备份；V4 Writer 不允许打开 V5 后降级保存，避免静默丢失新字段。

回滚不承诺旧 App 直接写入 V5。回滚方式是恢复升级前备份或使用新版导出的原始来源和笔记；界面和发布说明必须诚实说明这一点。

## 11. 隐私与资源边界

- 原始音视频、图片和 PDF 默认只在本机提取；摘要端点只接收经过标准化的文本块、必要 metadata 和证据 ID。
- 凭据只存在钥匙串；Workspace、诊断和测试 fixture 不保存密钥。
- 不读取浏览器 Cookie，不绕过登录、付费、DRM 或平台权限。
- 临时媒体位于 run 级目录，成功、失败、取消后清理。
- 网络、文件、文本块、OCR 页面、媒体时长、模型响应均有硬上限；超过上限时给出可行动提示，不让 App 无限制占用内存和磁盘。
- 用户取消后停止后续模型调用；已发出的外部请求迟到也不得提交结果。

## 12. 工程验证和产品验收

### 12.1 工程验证通过

至少覆盖：

- V4 → V5 迁移、回滚保护、确定性编码；
- 标准化内容、指纹、覆盖状态和证据 Validator；
- 每种格式的离线 fixture；
- 小红书视频、图文和登录/页面变更失败 fixture；
- 平台路由隔离，证明小红书视频不会进入 B 站适配器；
- SSRF、重定向、大小上限、敏感查询串脱敏；
- OCR/转写局部失败后的 partial/insufficient 判定；
- 长材料分块、证据回连、模型 JSON 截断和重试；
- 取消、迟到完成、来源变化、重启恢复；
- 旧摘要在重试期间保留；
- 写入笔记幂等且不覆盖用户块；
- 全量 `swift test`、Release 构建、最终 `.app` 构建与 codesign 验证。

### 12.2 产品实操通过

使用最终打包 App 和隔离但非空的真实数据，逐一完成：

1. 粘贴一段长文字并提炼；
2. 公共中文文章；
3. 用户提供的小红书视频笔记；
4. 一条小红书图文笔记，包含多张有字图片；
5. B 站公开视频；
6. 小宇宙公开单集；
7. 本地中英文音频和视频；
8. 数字 PDF 与扫描 PDF；
9. 平台受限后改用粘贴/文件继续；
10. 长材料、取消、失败重试、App 重启和确认写入笔记。

实操直接观察：

- 点击主操作后 300 ms 内出现可见反馈；
- 取消后 1 秒内出现可见状态变化；
- 进度文案与真实阶段一致，不展示虚假百分比；
- 摘要主要观点能展开到正确时间、页码、图片或段落；
- 部分内容不会伪装为完整摘要；
- 摘要失败后重试不重复 OCR/转写；
- 原始输入在失败、取消、重启和写入笔记后仍可访问；
- 结果布局在真实长内容下没有明显截断、跳动和操作歧义。

300 ms 和 1 秒只衡量本地可见反馈，不把网络、OCR、Whisper 或模型总耗时伪装成 App 响应时间。

### 12.3 用户验收通过

工程验证和产品实操只证明候选交付物达到可验收状态。用户本人在真实日常材料上使用后明确认可，才能把“10 分体验”从 `UNVERIFIED` 改为通过。

主观验收重点：

- 不需要先理解内容格式或平台；
- 等待过程安心，随时知道 App 在做什么；
- 摘要准确、有用，而且能快速回到原文核对；
- 平台失败时仍然能继续完成任务；
- 写入笔记前有控制感，写入后没有重复和脏内容。

## 13. 实现顺序和依赖

本节只确定架构依赖，不代替后续逐文件实现计划。执行拆成三个连续计划，避免一个超大计划同时改领域模型、所有格式和平台：

- 计划 A：V5 标准化材料、证据、迁移、统一路由，以及 B 站/小宇宙回归；
- 计划 B：文字/HTML、Vision/PDFKit、音视频文件和长材料摘要；
- 计划 C：小红书视频/图文、失败回退、最终 App 实操与用户验收候选。

计划 B 依赖 A，计划 C 依赖 A 和 B 的格式提取器。任何计划都不能单独被报告为整个“10 分体验”完成。

1. 冻结 V5 标准化材料、证据和迁移合同；没有这一层，不接新平台。
2. 改造 Coordinator、摘要合同和 UI 状态，使旧 B 站/小宇宙在新管线回归通过。
3. 接入直接文字、HTML、图片、PDF、音视频文件提取器。
4. 接入小红书视频和图文适配器，复用格式提取器。
5. 加入长材料分块、部分覆盖展示和粘贴/文件恢复路径。
6. 完成安全、性能、最终 App 实操和用户验收。

每一阶段都必须保持原始灵感可用并通过迁移/回归门禁。局部平台 fixture 通过不得报告为多格式产品实操通过。

## 14. 最终非目标

- 不承诺所有网页、所有平台或所有受限内容都能直接抓取。
- 不把 MaterialSnapshot 暴露成新的一级资料库。
- 不自动把摘要升级为知识、任务或日程。
- 不在捕获后自动开始昂贵提炼。
- 不用 LLM 猜测没有取得的图片、视频画面或正文。
- 不以测试数量替代最终 App 真实材料实操和用户本人验收。

## 15. 决策摘要

- 选择：格式优先统一管线 + 薄平台适配器。
- 稳定边界：公开内容和本地文件；受限内容提供粘贴/文件回退。
- 核心新模型：MaterialSnapshot + 带 locator 的 MaterialBlock。
- 核心质量机制：内容足够性、partial 明示、长材料分块、结论证据回连。
- 第一阶段平台：保留 B 站、小宇宙，新增小红书视频和图文。
- 第一阶段格式：文字、公共文章、TXT/Markdown/HTML、图片、PDF、音频、视频。
- 运行边界：本机提取媒体和 OCR，OpenAI 兼容端点只接收标准化文本。
- 验收边界：工程、最终 App 实操、用户本人 10 分认可三层分开。
