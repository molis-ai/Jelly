# Jelly iOS 开发记录

建立：2026-09-26；更新：2026-09-27。桌面基线：`4c90538`。开发在独立 `jelly-ios` 工作树进行。

## 原始要求

按照桌面 Jelly 开发 iOS App，完整保留现有功能。视觉与交互沿用桌面风格，适配移动端操作习惯，可参考滴答清单移动端。不能以只做日历或静态页面替代完整目标。

## 真实使用闭环

随手捕获文本、链接或文件到灵感 → 阅读原文、摘要 → 转为结构化笔记 → 把笔记或其中待办安排到日历 → 查看、改期和完成 → 回看进展。分类、搜索、撤销、持久化、备份恢复贯穿各模块。重复事项与笔记关系使用同一套桌面领域规则。

## 实现决定与必要性审查

- 原生 SwiftUI iOS 17+，iPhone/iPad。复用 CalendarDomain、WorkspaceDomain、CalendarPersistence 与平台独立 WorkspaceStore，不新增另一套业务模型、数据库或简化事务规则。
- 原生移动视图与桌面 AppKit 视图分别实现；用 Xcode 源码引用共享控制器，避免为此搬迁或大规模 public 化整个桌面 App。
- 底部日历、笔记、灵感三个主入口。日历月/周与当天明细；手机的快速添加用底部表单，详情用导航或全屏编辑；长按菜单、侧滑操作与可见按钮互补。
- 保留桌面暖纸色 `#F7F1E7`、暖黑色 `#211E1B`、陶土色强调、分类色块；触控热区至少 44pt，动态字体、深浅色、安全区和键盘避让。
- 独立沙盒目录和 bundle ID。开发、测试均不能写入桌面日用数据库；本工作不替换已安装 Jelly；原构建 Goal 不含提交、推送、发布，后续提交授权见下节。
- 当前不新增滴答的番茄钟、习惯、第三方日历等桌面 Jelly 未实现的功能。

## 移植中发现的共享修复

2026-09-27 的真实草稿冲突恢复验证发现：用户确认把当前输入恢复为主笔记时，旧实现只同步关联待办的完成时间，未同步改变后的标题；一致性校验因此拒绝恢复。现对 `WorkspaceStore.recoveredCurrentState` 做窄修复，复用 `TaskBlockCalendarTitle.normalized` 同步日历标题与更新时间，保留日历完成状态、原子候选校验和原恢复授权。该 helper 仅开放现有算法供应用层调用，没有新增另一套规范化规则。

这是完成既有“冲突后选择版本并继续编辑”闭环所必需的共享修复，无需求删除或放宽。原启动 Journal 的三个失败经过独立复现与另一处窄修复处理，证据单独登记。开发修改仍只在隔离工作树，回滚可单独撤回这段恢复标题补丁，不涉及日用数据迁移。

随后用真实 JSON 文件复现到启动清理风险：主文件不可读时，旧内存中相同的笔记不能作为草稿已经保存的证明。现只在 `verifyPersistedDraft` 核对当前来源、当前笔记内容与版本，并确认回执各字段相符后，才清除精确匹配的旧草稿记录；不可读、来源变化或未持久化均保留记录。Journal 文件格式、锁和事务机制未改。新增四项真实磁盘测试，原三项失败测试不改断言即通过；原“相同内容可清理”测试只补齐真实主文件落盘的前置条件。
