## 启动恢复问题：已复现并修复

首次受影响入口回归运行 212 个测试，出现以下 3 个失败、6 条 assertion issues。主 Agent 曾在未修改的原 `main@4c90538` 复现相同失败，没有将它们归因于 iOS 界面：

- `startupBareJournalWithUnreadableMainStaysProtectedAndNeverPublishesItsDraft`
- `concurrentStartupUnbindPublishesTheSameBareRecoveryInsteadOfParkingTheLoser`
- `startupPendingPreviousUnbindDoesNotLeaveALaterSavedReceiptBehind`

独立诊断确认“内容相同即清理”分支跳过当前主文件核验；真实 JSON 路径在主文件不可读时也会用旧内存清掉保护记录。现清理前调用原 `verifyPersistedDraft`，核对当前笔记内容、版本与来源及回执字段；失败保留精确记录。原三项测试没有改动，修复后全部通过。新增测试覆盖正常清理、不可读、外部改写和仅初始内存而未落盘；既有正常清理测试只补齐真实主文件落盘的前提，保留行为断言。Journal 格式、锁和事务未改。

另一处显式恢复修复位于 `recoveredCurrentState`：恢复关联待办的新标题时同步日历标题，继续以已保存日历的完成状态为准，避免两端标题不一致导致恢复被拒绝。真实三种恢复选择已覆盖恢复后重读与继续编辑。

主 Agent 在最终共享修复后实际运行：

