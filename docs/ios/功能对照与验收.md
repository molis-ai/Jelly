## 原始承诺与当前边界

用户要求按照桌面 Jelly 开发原生 iOS App，完整复刻现有功能；视觉与交互沿用 Jelly 风格，并遵从移动操作习惯，可参考滴答清单移动端。

**原承诺不减项、不降低完成程度。** 下面每一行都是需要处理的功能或语义，分期实现不等于取消。尚未移植、受平台限制、尚未接通的能力必须明确留下状态，不能用空按钮、模拟结果或仅有数据结构代替。滴答清单只提供移动交互参考，不自动引入 Jelly 没有的习惯、番茄、团队协作等额外产品范围。

2026-09-27 已使用 Xcode 27.0 与真实 iOS SDK 构建成功，App 已安装并启动于 iPhone 17 / iOS 27.0 模拟器；日历首屏与新增表单实际可见。日历、笔记、文字灵感基础旅程及进程重启已由 XCUITest 实际操作通过，并核对截图与落盘数据；完整功能组合仍待验证。下表的源码/共享层证据不能扩展成完整 iOS 或真机验收通过。

双端数据同步的预期尚待用户答复。当前不得擅自选择 iCloud、共享目录、桌面常驻服务或新增云端作为唯一真相源。独立本机工作空间、备份导入和实时同步是三种不同交付，必须在答复后确定；已有完整功能复刻承诺保留。

桌面 MCP 功能不能静默删除。可研究前台运行时保留本机 HTTP MCP，但 iOS 后台常驻、其他设备访问和桌面 stdio 桥不是同一种能力；需明确实际使用设备、客户端、连接入口与平台生命周期后确认对应路径。不得将 iOS 的 `127.0.0.1` 告诉 Mac 客户端并宣称已连通。

## 平台障碍与依赖顺序

1. **锁定事实与保护桌面。** 使用隔离工作树和 iOS 独立数据目录，保留桌面现有改动、日用 App 和数据；建立本矩阵，不从 README 旧状态删需求。
2. **复用数据与事务。** CalendarDomain、WorkspaceDomain、CalendarPersistence维持唯一业务语义；适配平台依赖并建立 iOS target，不能另造简化 store。导入桌面备份与双端实时同步分开决定。
3. **完成主闭环与移动编辑。** 日历→事项→笔记→待办安排→完成联动；灵感→原始材料→笔记；分类、搜索、撤销、恢复贯通。UIKit编辑必须保留结构与输入法组合状态。
4. **接真实服务。** 材料获取、文件沙盒、OCR/PDF/媒体、本机转写、远端摘要、FoundationModels/手动拆分依次接通，保持同一域合同；不要用假结果过门禁。
