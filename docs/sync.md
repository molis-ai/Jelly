# Mac 与 iPhone 同步

Jelly 不依赖服务器，也不需要开发者账号或 iCloud 容器权限：两台设备在各自的设置里选**同一个文件夹**（Mac 默认 `iCloud Drive/Jelly 同步`，iPhone 在「文件」里选同一个），由 iCloud Drive 负责搬文件。

## 文件

```
<同步文件夹>/jelly-sync-v1/devices/<设备ID>.json
```

每台设备只写自己的那个文件，所以 iCloud 不会生成「文件名 2」这类冲突副本。文件内容是 `SyncDeviceDocument`（`Sources/WorkspaceDomain/WorkspaceSync.swift`）：

| 字段 | 含义 |
| --- | --- |
| `format` | 目前是 1。读到更高版本的文件会停止同步并提示升级，不会猜着合并 |
| `deviceID` / `deviceName` | 设备身份，ID 在第一次同步时生成，存在本机偏好里 |
| `uncategorizedID` | 各设备最终统一到最小的那个“未分类”id |
| `clock` | Lamport 时钟：本机发出的最大时间戳，之后的编辑一定更大 |
| `seen` | 已合并进这份文件的各设备最大时间戳，用来判断两次笔记修改是不是互不知情 |
| `entries` | 记录键 → `{ts, device, value}`；`value` 为空表示删除（墓碑） |

记录按对象拆分：分类、事项、重复系列、例外、完成、笔记正文、灵感、材料摘要、无日期事项、日历–笔记关系、任务块链接、灵感–笔记链接。本机另存 `数据目录/sync/meta.json`，记着上次合并后每条记录的哈希，用来发现两次同步之间本机改了什么。

## 合并规则

1. 本机两次同步之间改过的记录打上新时间戳（取「当前毫秒」和「时钟 + 1」的较大者）。
2. 每条记录取 `(时间戳, 设备ID)` 最大的版本；删除也是一个版本，所以过期的旧文件不会把删掉的东西带回来。
3. 同一篇笔记在两台设备上都改过、且双方都没见过对方的改动时，输掉的一版另存为「原标题（冲突副本）」。副本 id 由内容决定，两边都生成也只有一份。
4. 合并后先修复跨记录引用（指向已删除笔记的关系、同名分类、编号不连续的分类顺序、源已变化的摘要等），再过与本地编辑相同的校验器；过不了就放弃这一轮，本机数据不动。
5. 合并结果通过 `restoreContent` 一次写入，编辑菜单里显示为一步「同步」，可以撤销。合并期间本机又有修改则放弃本轮，几秒后重试。

## 什么时候同步

改动后约 8 秒、每 2 分钟、App 回到前台时。设置里有「立即同步」。

## 不同步的内容

摘要服务与密钥、本机命令选择、快捷键、提醒事项权限与映射、界面偏好——这些各设备分开设置。

## 验证

- `swift test --filter WorkspaceSyncEngineTests`：加入已有数据、编辑与删除往返、过期文件不复活、并发笔记冲突副本、顺序编辑不产生副本、悬空引用修复、新字段、格式版本、60 轮随机编辑后两端记录完全一致。
- `swift test --filter WorkspaceSyncServiceTests`：两个真实 `WorkspaceStore` 经临时文件夹交换、删除传播、iCloud 占位文件与损坏文件。
- 尚未做：两台真机经 iCloud Drive 的实际往返（本机没有 Xcode 与真机）。
